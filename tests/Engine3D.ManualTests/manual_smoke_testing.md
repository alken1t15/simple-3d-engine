# Ручной smoke-тест #13

## Что это

Ручной smoke-тест проверяет MVP demo на реальном графическом стенде: картинку, глубину, текстуру, движение, свет, циклы запуска и граничные сценарии API. Он не заменяет CPU-тесты и CI: автоматические проверки не подтверждают, что окно показывает ожидаемую сцену.

Харнесс `tests/Engine3D.ManualTests` запускает 13 кейсов из issue #13. Визуальные кейсы требуют подтверждения соответствия реального поведения ожидаемому, API-кейсы выполняются автоматически с подтверждением штатного завершения.

## Запуск

```sh
dotnet build Engine3D.sln -c Release                                            # собрать движок и Demo
dotnet build tests/Engine3D.ManualTests -c Release                              # собрать харнесс
dotnet run --project tests/Engine3D.ManualTests -c Release --no-build -- --all  # запустить все 13 кейсов
```

Отдельные команды:

```sh
dotnet run --project tests/Engine3D.ManualTests -c Release --no-build -- --list    # показать список кейсов
dotnet run --project tests/Engine3D.ManualTests -c Release --no-build -- --case 4  # запустить только кейс 4
dotnet run --project tests/Engine3D.ManualTests -c Release --no-build -- --help    # показать справку
```

Положение и размер окна сохраняются в `artifacts/manual-tests/13/window-placement.txt` и переиспользуются следующими кейсами. Окно можно перетащить или изменить его размер, следующее окно откроется там же.

## Шаги воспроизведения

- Визуальный кейс: окно открыто, пока вы не ответите. Нажатие `y` — увиденное совпало с ожидаемым, нажатие `n` — не совпало.
- Автоматический кейс: после завершения подтвердите, что не было окна аварийного завершения ОС.
- `PASS` — проверка пройдена, `FAIL` — не пройдена, `SKIP` — условие не воспроизводится на текущей платформе.
- Автоматические запуски Demo ограничены 120 секундами; при зависании процесс и дерево процессов останавливаются, кейс завершается с `FAIL`.

## Тест-кейсы

| № | Тип | Действие | Ожидаемый результат |
|---:|---|---|---|
| 1 | Визуальный | Запустить `--case 1` | Открывается справка Demo без окна. В ней есть запуск MVP и параметры проверки. Ответ `y`, если справка полная. |
| 2 | Визуальный | Запустить `--case 2` | Окно `--static`: видны текстурированный куб и плоскость, объекты не перекрываются случайно и находятся на своих местах. |
| 3 | Визуальный | Запустить `--case 3` | Куб находится перед плоскостью и перекрывает ее; пол и грани не просвечивают, нет мерцания глубины. |
| 4 | Визуальный | Запустить `--case 4` | Буква `F` не зеркальна и не перевернута. Верхние углы текстуры: левый — синий, правый — желтый; нижние: левый — красный, правый — зеленый. |
| 5 | Визуальный | Запустить `--case 5` | Два отдельных окна: в первом вращается только куб, во втором куб неподвижен и двигается только камера. |
| 6 | Автоматический | Запустить `--case 6` | Три процесса Demo и три цикла `Engine.Create → Run → Dispose` в одном процессе завершаются штатно, без ошибок ОС. |
| 7 | Автоматический | Запустить `--case 7` | Неверный размер окна отклоняется; второй `Run`, `Run`/`LoadTexture` после `Dispose` и повторный `Dispose` обрабатываются по контракту, без падения процесса. |
| 8 | Автоматический | Запустить `--case 8` | Исключение в `onUpdate` прерывает `Run`, исходная ошибка сохраняется, ресурсы освобождаются, новый `Engine` показывает сцену. |
| 9 | Автоматический | Запустить `--case 9` | `RequestClose` завершает Demo; отсутствующий, битый, неподдерживаемый и недоступный файл дают путь и причину, завершение штатное. |
| 10 | Автоматический | Запустить `--case 10` | На Linux: `Create` без доступного дисплея дважды завершается `PlatformUnavailable`, после восстановления `DISPLAY` новый `Engine` создается. На macOS/Windows — `SKIP`. |
| 11 | Визуальный | Запустить `--case 11` | Сцена `--scenario lighting`: смена направления света меняет яркость граней; текстура и перекрытие по глубине остаются корректными. |
| 12 | Визуальный | Запустить `--case 12` | Сцена сохраняется в JSON. После загрузки в новом процессе картинка совпадает: объекты, transform, материалы, текстура, камера и свет. |
| 13 | Автоматический | Запустить `--case 13` | Битый JSON, отсутствующая текстура и сцена без загрузчика дают ошибки контракта с понятным сообщением; некорректная сцена не показывается. |

## Результаты прогона

Дата: 2026-10-17.
Стенд: macOS, .NET 10, OpenGL через OpenTK.
Команда: `dotnet run --project tests/Engine3D.ManualTests -c Release --no-build -- --all`.

Итог: **12 PASS, 1 SKIP, 0 FAIL**. Проблем не выявлено.

- Кейсы 1–9 и 11–13: ожидаемое поведение совпало с фактическим.
- Кейс 10: `SKIP`, потому что проверка отказа контекста воспроизводится только на Linux.
- Визуальные кейсы 2–5, 11 и 12 подтверждены вручную; автоматические кейсы 6–10 и 13 завершились без ошибок ОС.

## Ограничения

- Визуальная проверка субъективна и не проверяет FPS или производительность.
- Нет программного сравнения данных после загрузки JSON: сценарий D подтверждается глазами.
- В кейсе 9 недоступный файл проверен на macOS; при запуске от root эта подпроверка может дать `SKIP`.
- Linux-ветка `context-failure` собрана, но на Linux/X11 не запускалась.
