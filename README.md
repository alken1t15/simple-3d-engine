Учебный проект: небольшой **3D-графический движок на C#** с публичным API. Создан C# solution со сборкой в CI, реализованы CPU-модели сцены в `Engine3D.Core` (#7), процедурные примитивы (#8) и базовый OpenGL-рендер с освещением в `Engine3D.OpenGL` (#9), все с тестами. Требования, архитектура и порядок разработки описаны; загрузка текстур, сохранение сцены и демонстрационное приложение еще не реализованы.

## Структура solution

`Engine3D.sln` содержит ровно четыре проекта:

| Проект | Назначение | Ссылки на проекты |
|---|---|---|
| `src/Engine3D.Core` | Модель сцены и CPU-данные без окна и OpenGL: `Vertex`, `MeshData`, `TextureData`, `MaterialData`, `Transform`, `Camera`, `Scene`, `SceneLighting` (#7), `PrimitiveFactory` (#8). | Нет |
| `src/Engine3D.OpenGL` | Публичный `Engine` и `EngineOptions` (#9): окно и контекст OpenGL 3.3 через OpenTK, цикл `Run`, GPU-кэш мешей, depth test и базовый свет. Текстуры подключает #10. | `Engine3D.Core` |
| `src/Engine3D.Demo` | Исполняемое приложение для будущей демонстрации публичного API. | `Engine3D.Core`, `Engine3D.OpenGL` |
| `tests/Engine3D.Tests` | Тесты на MSTest: CPU-тесты Core и OpenGL-слоя без графического контекста, графические тесты `Engine` по `ENGINE3D_GRAPHICS_TESTS=1`. | `Engine3D.Core`, `Engine3D.OpenGL` |

Все проекты собираются для `net10.0`, с включенными `Nullable` и `ImplicitUsings`. `Engine3D.Core` содержит CPU-модели сцены, `Engine3D.OpenGL` — рендер на OpenTK 4.9.4; `Engine3D.Demo` пока содержит только каркас (#11). Декодер изображений будет добавлен вместе с загрузкой текстур (#10). Дополнительных архитектурных проектов нет.

[Контракт API версии 1](docs/api.md) определяет будущие типы, матрицы/UV, нормали, освещение, JSON собственной сцены и примеры A–D. Базовые детали контракта описаны по результатам spike #5; принятые в PR #26 контракты света/JSON сохранены. Наличие документа не означает реализацию функций.

## Сборка и запуск

Установите [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0): версию `10.0.112` или более новую стабильную версию `10.0.*`. `global.json` разрешает новые feature bands внутри .NET 10 (`rollForward: latestFeature`), но исключает preview и переход на другую major/minor-версию. Для первого восстановления тестовых пакетов нужен доступ к NuGet.

Из корня репозитория:

```sh
dotnet --version
dotnet restore Engine3D.sln
dotnet build
dotnet test Engine3D.sln
dotnet run --project src/Engine3D.Demo
```

Demo выводит сообщение о готовности каркаса и завершает работу; демонстрационное приложение появится в #11. Пример использования `Engine` — сценарий B в [контракте API](docs/api.md#5-сценарий-b--много-объектов-и-замер): с #9 он выполняется без изменений.

`dotnet test` запускает CPU-тесты без графического контекста: данные меша и текстуры, процедурные куб/плоскость, проверки, матрицы камеры и transform, сцену и свет, а также CPU-часть рендера — проверку опций `Engine`, поправку глубины для OpenGL, подготовку кадра и GPU-кэш по идентичности `MeshData`.

Графические тесты `Engine` открывают небольшие окна и проверяют жизненный цикл, перекрытие по глубине, переиспользование GPU-меша и свет по пикселям кадра. Им нужны дисплей и драйвер OpenGL 3.3, поэтому без переменной окружения они пропускаются:

```sh
ENGINE3D_GRAPHICS_TESTS=1 dotnet test Engine3D.sln
```

### Процедурная геометрия

```csharp
using Engine3D.Core;

var cube = PrimitiveFactory.CreateCube(2f);       // 24 вершины, 12 треугольников
var floor = PrimitiveFactory.CreatePlane(6f, 4f); // XZ, 4 вершины, 2 треугольника
```

Размеры должны быть положительными и конечными, иначе фабрика выбрасывает `ArgumentOutOfRangeException`.
Оба меша центрированы в начале координат. Куб имеет отдельные внешние нормали и UV на каждой грани;
плоскость обращена к +Y. UV (0, 0) снизу слева, обход треугольников — CCW снаружи, как в spike #5.
Фабрики сохраняют внутреннее описание типа и размеров для будущей сериализации #25; сама сериализация
не реализована. На предельно малых float-размерах половина размера может округлиться в ноль:
геометрия тогда вырождается, как допускает `MeshData`, но UV, нормали и описание размеров сохраняются.

### Проверки в CI

GitHub Actions на `push` и `pull_request` проверяет документы и выполняет:

```sh
dotnet restore Engine3D.sln
dotnet build Engine3D.sln --configuration Release --no-restore
dotnet test Engine3D.sln --configuration Release --no-build
```

Отдельный job повторяет тесты с `ENGINE3D_GRAPHICS_TESTS=1` на виртуальном дисплее Xvfb с программным OpenGL Mesa (llvmpipe). Это проверка поведения и пикселей кадра, а не FPS или картинки на целевом GPU.

## Что планируется

- Сцена с несколькими объектами, камерой и преобразованиями `position / rotation / scale`.
- Простая полигональная геометрия: индексные треугольники, куб и плоскость.
- Отрисовка с корректной глубиной, базовым материалом и одной текстурой по UV.
- Фоновый свет и один направленный источник с рассеянной составляющей.
- Сохранение и загрузка собственной сцены в JSON, без импорта внешних моделей.
- Отдельное демо, которое использует публичный API без прямых вызовов OpenGL.
- Нагрузочная сцена примерно из 1000 простых объектов с воспроизводимым замером FPS.

Игровая логика, физика, коллизии и редактор сцен не входят в базовый объем. Точный статус каждого требования и граница MVP записаны в [плане](project_plan.md).
