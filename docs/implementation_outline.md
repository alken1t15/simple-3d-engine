# Псевдокод и порядок разработки

**Назначение:** пояснить, что делать в каждом модуле после этапа планирования. Это схема действий, **не реализация C#**. Контракты: [требования](requirements.md), [архитектура](architecture.md), [API](api.md). Spike завершен; контракты P0-10/11 (нормали/свет и JSON) приняты через [PR #26](https://github.com/alken1t15/simple-3d-engine/pull/26). В #6 описаны базовые детали API v1 и CPU-доступ renderer; созданы solution и build/test CI. Ниже учтены обязательный свет и JSON; это не реализованный код.

## 1. Общий сквозной путь

```text
Клиент создает Engine
  → создает MeshData, MaterialData, SceneObject, Scene и Camera
  → вызывает Engine.Run
  → Engine получает события окна и вызывает callback клиента
  → Renderer читает текущую сцену
  → Renderer создает GPU-ресурс только для новых mesh/texture
  → Renderer показывает кадр
  → клиент закрывает окно или вызывает RequestClose
  → Engine освобождает все GPU-ресурсы и контекст
```

Демо-приложение использует только публичный API. Логика «когда и куда двигать объект» остается в демо; движок хранит новое положение и отображает его.

## 2. Подготовка данных сцены (`Engine3D.Core`)

### 2.1. `MeshData`

```text
получить список вершин и список индексов
если вершин нет → вернуть понятную ошибку
если индексов нет или их число не кратно 3 → вернуть понятную ошибку
для каждого индекса проверить: 0 ≤ индекс < число вершин
проверить конечность позиции/UV/нормали и ненулевую длину нормали
нормализовать нормали в собственной копии
скопировать данные в собственное неизменяемое хранилище; публичный доступ через ReadOnlySpan
посчитать число треугольников = число индексов / 3
```

Критерий: неверные входные данные не достигают OpenGL; один `MeshData` может использоваться несколькими объектами. Нормали обязательны для P0-10; скелет и наборы подмешей не добавлять. Фабрики сохраняют внутреннее описание cube/plane для #25, произвольный mesh не обязан сериализоваться.

### 2.2. Фабрика примитивов

```text
CreatePlane(width, depth):
  проверить положительные конечные размеры; иначе ArgumentOutOfRangeException
  создать 4 вершины в плоскости XZ с определенными UV и нормалью +Y
  создать 2 треугольника
  вернуть MeshData

CreateCube(size):
  проверить положительный конечный размер; иначе ArgumentOutOfRangeException
  для каждой из 6 граней создать вершины с собственными UV и внешней нормалью грани
  добавить 2 треугольника на грань
  вернуть MeshData
```

Для куба **не обещать ровно 8 GPU-вершин**: чтобы каждая грань получила свои UV, вершины на общих геометрических углах могут дублироваться. Критерий: контрольная текстура различимо лежит на гранях, индексы не выходят за пределы, winding одинаков.

### 2.3. `Scene`, `SceneObject`, `Transform`, `Camera`

```text
Scene.Add:
  проверить, что объект не null и не добавлен повторно
  добавить ссылку на объект в коллекцию

Scene.Remove:
  удалить ссылку; mesh/texture при этом не освобождать

Transform:
  хранить position, quaternion rotation, scale
  проверить ненулевой конечный quaternion, нормализовать его для расчета model matrix из текущих значений

Camera:
  проверить параметры near/far/FOV
  получить view matrix из position/target/up
  получить Core projection matrix из FOV и aspect ratio framebuffer, depth [0,1]
```

Критерий: изменение transform между кадрами меняет положение объекта; удаление объекта из сцены не ломает другой объект, использующий тот же mesh. По завершенному spike: row-vector model = scale * rotation * translation, MVP = model * view * projection; UniformMatrix4 transpose=false. Для нормалей использовать inverse-transpose линейной части model и числовой тест перпендикулярности при неравномерном масштабе. Нулевой scale отклоняется до GL.

## 3. Инициализация и цикл окна (`Engine3D.OpenGL`)

```text
Engine.Create(options):
  проверить ширину, высоту и остальные параметры
  создать окно/контекст OpenGL
  подготовить базовый shader program и renderer
  если шаг не выполнен → освободить уже созданное и сообщить ошибку
  вернуть готовый Engine

Engine.Run(scene, camera, onUpdate):
  убедиться, что Engine не закрыт и Run не выполнялся ранее
  пока окно открыто и не запрошено закрытие:
      обработать события ОС
      если запрошено закрытие → выйти из цикла
      вычислить время с прошлого обновления; для первого update deltaSeconds = 0
      вызвать onUpdate в вызывающем приложении
      если onUpdate запросил закрытие → выйти без нового кадра
      при нулевом framebuffer пропустить render/swap/счетчик
      построить и показать кадр из текущей scene/camera
      увеличить RenderedFrames после фактического показа кадра
  выйти из цикла
```

Callback не должен превращаться в игровую подсистему движка: он только предоставляет приложению момент для изменения данных. `Engine.Run` владеет циклом окна; отдельного публичного `Initialize` и параллельного ручного цикла в P0 нет. Критерий: закрытие крестиком и `RequestClose` завершают цикл предсказуемо, повторный вызов `Run` отклоняется понятной ошибкой. Refresh перерисовывает последнее состояние без onUpdate; каждый успешный swap учитывается в RenderedFrames. Методы Engine выполняются на потоке Create; ошибки native callbacks сохраняются и выбрасываются после выхода из GLFW, не через native callback.

## 4. Подготовка GPU-ресурсов и кадр

```text
GetGpuMesh(meshData):
  если этот экземпляр MeshData уже есть в кэше → вернуть существующие буферы
  иначе создать вершинный и индексный буферы
  прочитать Vertices/Indices через ReadOnlySpan только на время upload
  загрузить неизменяемые данные
  запомнить связь MeshData → GPU mesh
  вернуть GPU mesh

GetGpuTexture(textureData):
  если этот экземпляр TextureData уже есть в кэше → вернуть существующую текстуру
  иначе прочитать Pixels через ReadOnlySpan
  перевернуть CPU RGBA8-строки сверху вниз ровно один раз в upload-буфере
  загрузить RGBA-пиксели в GPU
  выставить базовые параметры фильтрации/адресации
  запомнить связь TextureData → GPU texture
  вернуть GPU texture

RenderFrame(scene, camera):
  после onUpdate проверить camera/light/material и все transform до любых GL-вызовов
  построить model/normal matrices, проверить обратимость; нормализовать ненулевые rotation
  очистить color/depth
  вычислить view/projection для текущего framebuffer
  умножить Core projection справа на Identity с M33=2/M43=-1 для OpenGL depth [-1,1]
  передать M11..M44 с transpose=false
  для каждого SceneObject:
      получить mesh и необязательную texture через кэш
      вычислить model matrix и inverse-transpose normal matrix
      задать цвет материала, флаг текстуры, матрицы и свет
      shader: albedo * (ambient + directionalColor * max(dot(normal, -direction), 0))
      вызвать отрисовку индексированных треугольников
  показать готовый кадр
```

Нагрузка ~1000 объектов требует **мало уникальных mesh/texture**, но много transform. Первую реализацию делать с прямым обходом объектов. Если ориентир FPS не достигнут, измерить, где расходуется время, и только после этого рассматривать batch/instancing. Критерий: GPU-ресурсов не становится тысяча копий при тысяче ссылок на один `MeshData`; ближний объект перекрывает дальний.

## 5. Изображения и материал

```text
Engine.LoadTexture(path):
  проверить наличие и читаемость файла
  до Run декодировать PNG в CPU RGBA8 со строками сверху вниз
  не переворачивать строки и не загружать данные в GPU
  создать неизменяемый TextureData с полным SourcePath (копия RGBA8)
  вернуть его вызывающей программе

MaterialData:
  хранить базовый цвет и необязательную ссылку на TextureData
  при отсутствии текстуры показывать цвет
  при наличии текстуры применять ее по UV
  умножить RGB материала/текстуры на базовый ambient+diffuse свет
```

Критерий: собственная контрольная PNG с разными цветами по углам отображается без зеркала/переворота; неверный путь дает понятную ошибку. Несколько слотов, нормальные карты и PBR после P0 не закладывать в публичный контракт.

## 6. Завершение и ошибки

```text
Engine.Dispose:
  если уже закрыт → завершить без ошибки
  если вызван внутри onUpdate → InvalidOperationException; закрывать через RequestClose
  удалить все GPU mesh, texture и shader program до уничтожения контекста
  ошибка одного удаления не отменяет остальные и не скрывает исходную ошибку Run
  освободить окно/контекст в допустимом порядке
  пометить Engine как закрытый
```

`Scene.Remove` и сборщик мусора не удаляют GPU-ресурс. Единственный владелец — `Engine`; он освобождает кэш целиком. Для P0 не реализовывать счетчики ссылок и произвольную выгрузку ресурса посреди демонстрации. Критерий: несколько новых экземпляров `Engine` последовательно создаются и закрываются без падения и устойчивого роста памяти.

## 7. Демо, нагрузка и проверки

### Демо A: базовый функционал

1. Создать окно, куб, плоскость, камеру и контрольную текстуру.
2. Разместить куб и плоскость на разных глубинах.
3. В callback менять угол куба; дать пользователю увидеть смену ракурса камеры.
4. Проверить UV, цвет, depth и завершение.

### Демо B: около тысячи объектов

1. Создать **один** кубический mesh и материал, затем около 1000 `SceneObject` с различными transform.
2. Разместить их так, чтобы камера действительно показывала существенную часть сцены; записать число видимых объектов и треугольников.
3. Зафиксировать ноутбук, разрешение, VSync, прогрев и длительность замера.
4. Считать показанные кадры, а не вызовы update callback; записать средний FPS и длительные просадки.
5. Закрыть окно и повторить запуск для проверки освобождения ресурсов.

### Тесты по моменту добавления

| Когда | Проверить | Критерий |
|---|---|---|
| После `Core` | MeshData, индексы, примитивы, transform, камера | Числовые тесты и проверки ошибок проходят без GPU. |
| После первого рендера | Одна и та же сцена через публичный API | Цветной куб и depth визуально верны; нет прямых `GL` вызовов в демо. |
| После текстуры | PNG, UV, отсутствие файла | Контрольная ориентация верна; ошибки понятны. |
| После нагрузки | Переиспользование mesh, FPS, память, закрытие | Протокол замеров воспроизводим на выбранном ноутбуке. |
| После каждого PR | Старые unit/integration/smoke проверки | Регрессия не прошла незамеченной. |

## 9. Свет и JSON: реализация расширений C/D

### Свет (#7/#8/#9/#10)

Scene.Lighting хранит ambientColor/directionalColor и мировое направление лучей. Каждый кадр после onUpdate renderer проверяет ненулевое конечное направление и нормализует его, нормаль переводит в world space inverse-transpose и нормализует. В GLSL использовать transpose(inverse(mat3(u_model))) при проверенном способе передачи матриц. Изменяемые невалидные данные дают InvalidOperationException до GL. Для базового непрозрачного материала: albedo = baseColor.rgb * texture.rgb (либо *1); RGB = clamp(albedo * (ambient + directionalColor * max(dot(normal,-direction),0)),0,1). Alpha не включает blending. Не добавлять тени/specular/PBR.

### JSON (#25, контракты #6)

```text
Save(path, scene, camera):
  проверить аргументы, данные camera/transform/material/light и описания примитивов
  назначить mesh id по ссылочной идентичности MeshData
  для каждого объекта сохранить meshId/transform/material
  для texture вычислить относительный путь от каталога JSON из полного SourcePath
  сохранить camera/light, schema version=1, построить JSON целиком
  записать файл; ошибка валидации не меняет файл, I/O-отказ не обещает atomic rollback

Load(path, textureLoader):
  прочитать JSON и полностью проверить DTO version/поля/числа/id/ссылки
  проверить cube/plane размеры, quaternion, scale, camera и light
  если используются текстуры и нет loader → InvalidOperationException до создания сцены
  создать mesh один раз на id через фабрики, новую Scene/Camera
  разрешить texturePath относительно каталога JSON в полный путь, кешировать по пути
  loader должен вернуть TextureData с соответствующим SourcePath; иначе ошибка
  восстановить material/transform/объекты/scene.Lighting, вернуть SceneSnapshot
  при любой ошибке не возвращать частичный результат и не менять существующую сцену
```

Core не зависит от Engine/OpenGL. JSON-DTO состоит из числовых массивов/скаляров, не из прямой сериализации System.Numerics или графа объектов. Для показанной сцены клиент передает engine.LoadTexture, после Create и до Run. CPU-тесты могут использовать TextureData-конструктор и тестовый loader без окна. Подробные schema1, ограничения SourcePath/примитивов, ошибки и C/D — [API, разделы 9–10](api.md#9-json-собственной-сцены-p0-11-25).

### Интеграция и проверки

После #6 CPU-контрактов #7/#8 дают данные и примитивы; #25 может разрабатываться параллельно renderer без ожидания демо. #11 использует готовые функции для C/D, #12 проверяет CPU-нормали и round-trip, #13 — визуальную приемку с текстурой/светом и ошибки загрузки. Для round-trip проверить общую ссылку mesh у двух объектов, независимость путей от cwd, один вызов loader на общий путь и сохранение камеры/света. Некорректные quaternion/normal/direction/scale/камера и битый JSON отклоняются согласно API. Финальный FPS #14 со светом, запись/чтение JSON вне прогрева и замера; #15 описывает реальное управление/сохранение, #16 проверяет P0-01…P0-11. Не считать расширения реализованными по этому псевдокоду.
