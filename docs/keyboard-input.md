# Клавиатура, мышь и курсор

Дополнение публичного API для клиентских приложений. Игровые команды, физика и прыжки
остаются в приложении; библиотека передаёт только ввод окна Engine.
Существующий `Run(scene, camera, Action<float>?)` и прежние клиенты совместимы.
Расширение для [Ball Adventure #16](https://github.com/alken1t15/simple-platformer/issues/16)
реализуется в движке; принятие upstream PR и точного game gitlink остаются отдельными шагами.

```csharp
engine.Run(scene, camera, deltaSeconds =>
{
    var input = engine.Input;
    if (input.WasPressed(InputKey.Escape))
        engine.RequestClose();
    // IsDown — удержание, WasPressed — одно нажатие без автоповтора.
});
```

## Контракт снимка

`Engine.Input` доступен только внутри `onUpdate` и на потоке `Create`.
До/после `Run`, вне callback или с другого потока — `InvalidOperationException`;
после `Dispose` — `ObjectDisposedException`. Полученный `InputSnapshot` — неизменяемое
значение: его можно хранить и читать независимо от следующего кадра и освобождения Engine.
`default(InputSnapshot)` означает отсутствие фокуса и все кнопки false.

Поддерживаются `A`, `D`, `Left`, `Right`, `Space`, `R`, `Escape`, `W`, `S`,
`LeftShift`, `RightShift`, `Enter`, `Up`, `Down`, `Tab` через `InputKey`,
без OpenTK-типов/оконных handles. Неизвестное значение enum во всех трёх методах
снимка вызывает `ArgumentOutOfRangeException`.
Численные значения прежних A..Escape (0..6) сохранены, новые добавлены в конец (7..14).

- `IsFocused`: у окна есть фокус.
- `IsDown(key)`: принятое удержание клавиши на конец обработки событий.
- `WasPressed(key)`: хотя бы одно новое нажатие в текущем пакете событий; системный автоповтор исключён.
- `WasReleased(key)`: хотя бы одно отпускание ранее принятого удержания в этом пакете.

События очищаются перед очередной обработкой оконных событий; снимок читается после неё
в `onUpdate`. Быстрые нажатие и отпускание между updates сохраняют оба фронта, даже если
на конец пакета `IsDown=false`. Несколько переходов агрегируются флагами, не счётчиками.
Refresh без `onUpdate` не создаёт нового снимка и не очищает события.
Повторное чтение Engine.Input в одном update возвращает тот же снимок, даже если
приложение изменило CursorMode. Ранее полученное значение не меняется.

## Указатель и координаты

`InputSnapshot.Pointer` — неизменяемый `PointerSnapshot`, default пустой:

- `Position: System.Numerics.Vector2` — от левого верхнего угла клиентской области,
  X вправо, Y вниз, в логических пикселях, с дробной частью.
- `Delta: Vector2` — сумма относительных перемещений за пакет событий, без множителя времени.
  В следующем кадре без движения — ноль. Нельзя повторно применять delta на каждом sim tick.
- `IsInsideClient` — позиция внутри `[0, clientWidth) × [0, clientHeight)`; resize
  учитывается в следующем snapshot. Это геометрическая проверка, не hit-test перекрытия другими окнами.
- `IsDown/WasPressed/WasReleased(MouseButton)` — Left/Right/Middle с теми же правилами
  агрегирования и focus, что у клавиш. Неизвестный enum — ArgumentOutOfRangeException.

В Normal используются координаты GLFW client area, а не framebuffer. Поэтому при DPI 2×
позицию не умножают на два: будущий overlay должен использовать размеры WindowBounds;
масштаб в физические пиксели renderer берёт отдельно из FramebufferSize.
Position опрашивается через `GLFW.GetCursorPos` после обработки событий. Кэш
`NativeWindow.MousePosition` не используется как текущее положение: на X11 при выходе
из окна может прийти только CursorLeave без нового MouseMove. Поэтому Position и
геометрический IsInsideClient обновляются и снаружи окна при сохранённом keyboard focus.
В Captured курсор скрыт, GLFW поддерживает неограниченную виртуальную позицию; Position
может выйти за client bounds, IsInsideClient тогда false. Для поворота использовать Delta.
Raw mouse motion не включается: контракт измеряется в логических единицах, а не аппаратных counts.
Колесо, текстовый ввод и геймпады не входят в это расширение.

Использованы публичные события OpenTK и их client coordinates:
[NativeWindow 4.9.4](https://github.com/opentk/opentk/blob/4.9.4/src/OpenTK.Windowing.Desktop/NativeWindow.cs),
[GLFW cursor position/mode](https://www.glfw.org/docs/3.3/input_guide.html#cursor_pos).

## Режим курсора

`Engine.CursorMode` принимает Normal/Captured. По умолчанию Normal. Все обращения —
на потоке Create; другой поток — InvalidOperationException, после Dispose — ObjectDisposedException.
Get разрешён до Dispose, включая после Run. Set разрешён до Run и в onUpdate;
после Run и в render/refresh callback — InvalidOperationException. Invalid enum —
ArgumentOutOfRangeException при допустимых потоке и lifecycle.

Вызов Captured во время Run без фокуса оставляет Normal. До Run настройка допустима,
но при показе без фокуса захват будет сброшен. Повторное присваивание того же режима
не очищает движение. Смена режима очищает накопленный mouse delta и подавляет первое
следующее событие движения, даже если между ними были пустые кадры. Остальные события
суммируются обычно. Snapshot, уже выданный текущему callback, остаётся неизменным;
приложение не применяет его delta при переходе экрана/режима.

В onUpdate явный Start/Continue может задать Captured; меню и pause задают Normal.
При focus loss движок принудительно задаёт Normal и сбрасывает данные ввода.
Возврат фокуса не восстанавливает прежний режим. Завершение Run, в том числе исключение
из onUpdate, освобождает cursor до возврата вызывающему коду.

## Фокус и активация

Потеря фокуса сразу очищает удержания и оба фронта; синтетический WasReleased не создаётся.
Нажатия без фокуса игнорируются. При первой активации и каждом возврате фокуса
клавиши первого пакета активации подавляются. Уже отпущенные клавиши становятся доступны
после этого пакета; зажатые требуют отпускания, затем нового нажатия.
Это предотвращает ложный прыжок и залипание после Alt-Tab. Первый настоящий ввод лучше
принимать после первого update активного окна.
Это же правило действует для трёх кнопок мыши. При отсутствии фокуса Pointer пустой;
первое движение после возврата фокуса обновляет позицию, но не создаёт delta.

На Linux/X11 rearm клавиш использует физический `XQueryKeymap` на уже принадлежащем
GLFW Display, с переводом клавиш через `GLFW.GetKeyScancode`. Запрос выполняется
только пока остаются заблокированные клавиши. Событийные KeyboardState/GLFW.GetKey
после focus loss очищены и не доказывают физическое отпускание; первый autorepeat
после возврата может выглядеть как новый press. Физический keymap сохраняет блокировку
до отпускания и также учитывает клавиши, нажатые/отпущенные без фокуса.
Handle не выходит из backend, второе окно/Display не создаются. На остальных backend
сохранён прежний путь KeyboardState; новый физический rearm проверен только на X11,
его поведение на Wayland-native/Windows/macOS этим исправлением не подтверждается.

Пауза симуляции, fixed-step и очередь игровых команд — ответственность приложения.
При нескольких sim ticks на один update фронт нужно потребить один раз. При отсутствии sim tick
команду можно сохранить до следующего шага; при потере фокуса такую очередь нужно очистить.
DeltaSeconds остаётся реальным временем и автоматически на паузу не ставится.

## Проверки и ограничения

CPU-тесты проверяют фронты, повтор, быстрый press/release, независимость снимка/клавиш,
очистку при потере фокуса, подавление активации и неверный enum.
Графические lifecycle-тесты проверяют чтение Input в callback, ограничения потока и Dispose.
Графическим тестам по-прежнему требуется `ENGINE3D_GRAPHICS_TESTS=1` и OpenGL 3.3.
Реальные клавиши и переключение фокуса проверяются отдельно на целевой ОС; CPU-тесты не заменяют их.
Дополнительные CPU-тесты проверяют pointer edges/позицию/delta, фокус, подавление движения,
resize bounds и совместимость значений InputKey. Графические тесты проверяют lifecycle
CursorMode, неизменность Input внутри callback и освобождение при ошибке.

Ручной пример, автоматический X11-прогон и ограничения — [input-testing.md](input-testing.md).
