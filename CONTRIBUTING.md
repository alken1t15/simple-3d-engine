# Как участвовать в проекте

Создан C# solution, реализованы CPU-модели Core (#7), примитивы (#8) и базовый OpenGL-рендер (#9); текстуры, JSON и Demo еще не реализованы. Начните с [плана](project_plan.md) и [требований](docs/requirements.md); подробный процесс описан в [development-process.md](docs/development-process.md).

1. Возьмите задачу с понятным результатом и критерием проверки. Укажите ответственного и проверяющего.
2. Создайте короткую ветку от актуального `main`.
3. Перед PR выполните доступные для задачи проверки и обновите связанную документацию.
4. В PR укажите задачу, результат, способ проверки и реальные ограничения.
5. Для PR остальных участников получите два человеческих `Approve` и успешные проверки CI; автор не принимает собственный PR. Собственные PR Team Lead (`alken1t15`) не требуют чужих ревью: он может выполнить merge самостоятельно после успешных проверок.

Сейчас CI проверяет комплектность документации и отдельно OpenTK spike: его тесты и графический smoke на виртуальном дисплее Xvfb с программным OpenGL Mesa. Проверки spike запускаются при изменениях `spikes/**` или его workflow. Основной `Engine3D.sln` собирается в отдельном build/test CI: CPU-тесты без графического контекста и отдельный job с графическими тестами `Engine` на Xvfb с программным OpenGL. Перед PR выполните команды сборки из [README](README.md); нужен SDK из `global.json`. `dotnet test` запускает CPU-тесты; при изменении `Engine3D.OpenGL` запустите и графические: `ENGINE3D_GRAPHICS_TESTS=1 dotnet test Engine3D.sln`. Зеленый CI **не означает** готовность основного движка или проверку производительности на целевом GPU; графические сценарии и FPS проверяются на целевом ноутбуке.

Не добавляйте чужие модели, текстуры, шейдеры или другой контент с неясными правами. Сведения о разрешенных сторонних материалах записывайте в [THIRD_PARTY.md](THIRD_PARTY.md).
